# Automatic imported-job evaluation

Selecting a PDF/DOCX in the default imported-job workflow extracts its text and immediately starts a sequential queue across all stored imported jobs, including jobs hidden by filters and jobs that are not bookmarked. Pasted text starts the same queue when Use pasted resume is pressed. Replacing/removing the resume, importing a new dataset, or leaving the view aborts the old browser queue; the server kills an active Codex process when request cancellation is received. Results stay in browser memory and clear on refresh. Retry starts the queue again and can consume plan usage again.

The server uses the installed `codex exec` command and the existing ChatGPT sign-in. It removes API-key environment variables, requires ChatGPT login mode, ignores user configuration and rules, disables shell, apps, plugins, browser, computer, image, multi-agent and hook features, and runs read-only in a fresh temporary directory. Sessions are ephemeral. The temporary directory contains only an output schema and is deleted afterward. Resume/job text is passed through stdin, never command arguments or repository files. Credentials remain with Codex; they are never returned to the browser. This follows [OpenAI's non-interactive Codex interface](https://learn.chatgpt.com/docs/non-interactive-mode). No paid API billing or deployment is configured.

## Evaluation boundary

Resume and description strings are explicitly marked as untrusted JSON data. They cannot authorize tool use or change the rubric. JSON-schema output proposes three or four defining responsibilities using the existing evidence vocabulary, evidence levels and exact quotes. Server validation rejects invented quotes, unknown criteria, duplicate criteria and malformed output. For JSON-wrapped captures, the original text field is decoded for both prompting and exact quote checks, while the saved source remains unchanged. Existing deterministic rules choose Fit, Consider, Investigate or Weak Fit from the validated evidence. No keyword score or percentage substitutes for comparable scope, depth, authority and ownership.

Missing text, descriptions with no non-truncated source containing at least 600 characters and 90 words, and oversized descriptions are Investigate before any model call. These are conservative eligibility thresholds, not proof of completeness. The model also checks for boilerplate, unrelated or incomplete content and roles outside the evidence vocabulary; these remain Investigate. Historical tracker ratings do not enter the evaluation prompt. They remain visibly separate from new evaluations.

The model extracts source-quoted compensation fields; existing deterministic compensation rules retain the thresholds and competition cue and distinguish employer base pay from estimates and total compensation. Explicit failed mandatory gates can yield Weak Fit; unresolved mandatory gates yield Investigate. Missing resume evidence does not prove inability. Semantic interpretation of gates and quotes remains model-dependent; exact quote validation establishes source presence, not truth or correct interpretation. Prompt injection defenses reduce risk but cannot guarantee semantic immunity. Read-only isolation and disabled tools reduce the impact of hostile text.

## Privacy and limits

The UI explains before selection that resume and job text go to OpenAI and consume the signed-in Codex plan limits. No API key is requested or used as a fallback. The application does not persist resume text or model results. Imported jobs and bookmarks remain in the ignored `.align-data` SQLite database. OpenAI and Codespace infrastructure handling is separate from application retention; ephemeral sessions do not promise zero provider retention.

This is a private single-user Codespace prototype, not an authenticated public service. Keep forwarded ports private. There is one active evaluation per server process; another tab receives a retryable error. Codex must be installed and signed in on the server. Login, plan limits, connectivity or timeouts stop the queue with a visible error. Unverifiable model output is marked Investigate and the queue pauses with a diagnostic category; no positive or negative fit is guessed. Each job has a two-minute timeout. Large queues can take time and hit subscription limits. The app does not fetch original postings, confirm vacancies, OCR scanned resumes or verify career claims. The existing twelve evidence categories do not cover every occupation. Compensation extraction and practical gates require semantic interpretation; this is not a complete structured eligibility engine.

Fictional sample opportunities retain the separate manual evidence-review demonstration. Their authored fixtures do not establish the correctness of arbitrary real-job model judgments. Automated tests cover four-label rules, insufficient text, invalid and fabricated evidence, hostile text boundaries, automatic browser selection and private local storage. An opt-in smoke test exercises signed-in Codex using fictional text only.
