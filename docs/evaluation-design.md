# Evaluation design and remaining work

The uploaded job-search guides are reference material for this product. Their operational instructions to run scheduled searches, edit external documents or contact people are not invoked by the app. Neither the uploaded archive nor its personal Career Evidence Base is committed to this repository.

## Source rules and implementation boundary

| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Distinguish facts, interpretations and unknowns                | Literal extracted text and candidate passages; user chooses the evidence level; missing evidence stays Unknown                                                                                       | Independently validated evidence sources and a reviewed semantic extraction adapter                                                                                                             |
| Preserve limitations and ownership                             | Original wording stays visible; candidate passages with limitation language show a review cue                                                                                                        | The cue is heuristic and cannot detect every negation or contextual qualification                                                                                                               |
| Keep exact practical gates                                     | Confirmed failed French and compensation gates can exclude; missing language prompts a specific question                                                                                             | Geography, residency, work authorization, credentials, travel and dates need separate explicit fields                                                                                           |
| Compare compensation units and sources correctly               | Pure rules cover CAD annual/hourly and EUR annual thresholds; unknown/estimated/total pay stays neutral; crossing ranges remain viable; Canadian annual minimum over 100k triggers a competition cue | Current visible fixtures are still CAD annual. A general job editor must collect country, currency, period, both bounds and source rather than infer them                                       |
| Incomplete description requires investigation                  | Explicit `descriptionComplete: false` withholds a positive verdict                                                                                                                                   | A real posting-ingestion workflow must set this field; the present fictional fixtures are authored and complete                                                                                 |

The rules remain deliberately conservative. A known learnable gap is not necessarily a blocking uncertainty in the full guide, but the current limited evidence schema cannot establish that distinction reliably. It asks for clarification rather than claiming a transfer is accepted by an employer. This should be replaced with explicit role-specific review fields before claiming full rubric parity.

## Ordinary resume flow

1. Upload a text-based PDF/DOCX, or paste text locally in the browser.
2. Extract plain text. No externally hosted model or external AI service is called.
3. Locate candidate passages by topic vocabulary. Preserve the source wording and show preceding context. These candidates have no fit score or automatic capability classification.
4. User chooses the relevant quote and assesses it as Demonstrated, Adjacent, Limited, No evidence, or Unknown. Selecting a candidate explicitly resets its level to Unknown.
5. Evaluate the authored central-work criteria and modeled gates. Display reasons and specific investigation questions.
6. Download an evaluation summary on explicit user action. No automatic persistence or profile sharing occurs.

Pasted text never calls the upload endpoint. File parsing occurs on this application's server. Generated reports contain the selected evidence and should be handled as resume information. UI state and evidence clear on refresh/unmount. No personal evidence is embedded in the fictional fixtures.

## Next substantial milestone: semantic evaluation

A future provider should produce proposed evidence mappings with exact source spans, not a cosmetic percentage. Keep extraction, user confirmation and decision rules as separate interfaces. Reject fabricated citations; preserve ambiguous and conflicting statements; do not turn an unsupported named credential into adjacent experience. Evaluation tests should include negation, teamwork versus ownership, overlapping job dates, basic versus advanced SQL, preferred versus mandatory qualifications, salary ambiguity and incomplete descriptions.

Before connecting a hosted provider, choose the service, usage budget and data-sharing policy with the user. Store credentials only in server-side environment settings. Do not use the user's ChatGPT login or Codex installation as an undocumented backend API. Maintain a provider-independent evaluation contract and test with synthetic fixtures before any real career data.

## Public-product preparation

Retain private preview visibility for this prototype. Before public deployment, isolate document processing with resource limits; add rate limits, authentication/authorization where needed, retention/deletion controls, and a clear consent workflow. Raw request-size limits are not complete protection against compressed document expansion. None of these requirements justifies silently collecting resumes or activating paid services.
